# Skill catalog

Generated by `make skills-catalog` from the header of each skill in `agent/skills/`. Do not edit by hand.

## Core skills

| Skill | Stage | What it does |
|---|---|---|
| `/bug-bash` | Deliver | Runs a testing session on one area - one dated parent ticket, then each request from the tester becomes a sub-ticket and one commit, all in one worktree and one pull request. |
| `/commit` | Deliver | Stages the ticket's files by name and writes one commit in the project's commit format, after the project's checks pass. |
| `/continue` | Build | Picks up a ticket whose work stopped and says where it stands and what is left, as an ordered list. |
| `/create-spec` | Plan | Writes the spec of one ticket from its discovery, saves it in the Linear ticket and as a local copy. |
| `/cycle-mode` | Plan | Daily use of the cycle plan, where each message logs time, ticks a task, reschedules an item or refreshes the plan from Linear. |
| `/execute-spec` | Build | Creates the worktree of one ticket, executes only that ticket's spec inside it, runs the project's checks and writes the log. |
| `/fix-pr` | Deliver | Fixes the review comments that validate-comments confirmed, inside the ticket's worktree, runs the checks, commits, and pushes or asks as the profile says. |
| `/help-skills` | Start | Lists every skill available in this repository, grouped by stage, with what each one does and how to call it. |
| `/new-app` | Build | Creates the skeleton of a new app inside the monorepo, with the same structure as the existing apps. |
| `/new-module` | Build | Builds a new business module in three phases (an approved model, a parent ticket with sub-tickets, then the sub-tickets one by one) and continues a module that was started. |
| `/open-pr` | Deliver | Pushes the ticket's branch and opens its pull request to the base branch (or asks first, as the profile says), then reviews the pull request against the ticket's acceptance criteria. |
| `/plan-cycle` | Plan | Builds the plan for one cycle (one week of work) from Linear, with an estimate and a task list per ticket, and saves it with a snapshot in local-docs. |
| `/refine-ticket` | Plan | Reads a ticket with its parent, siblings, sub-tickets and related tickets, the docs and the code, marks each acceptance criterion as existing, partial, new or unclear, asks about the gaps and writes discovery.md. |
| `/release` | Deliver | Prepares the release ticket and the text of the release pull request from what was merged since the last release. |
| `/review-diff` | Deliver | Reviews the local changes of the current worktree against the project's rules and the ticket's spec, and changes nothing. |
| `/setup-local` | Start | Walks from make doctor to a working setup on this machine, fixing each failing check, then make setup, local-docs and the sign-in to Linear and GitHub. |
| `/start` | Start | Asks what the person wants to do and names the skill to run; the first time in a repository it also fills the project profile. |
| `/validate-comments` | Deliver | Checks every still-open comment on a pull request against the latest code and writes a file with a verdict, what to do and a draft reply per comment. |

## Skills of this project only

| Skill | Stage | What it does |
|---|---|---|
| `/build-component` | Build | toraline-ui - Builds one component of the library in code from its approved design brief and its Figma component (the component with Tailwind classes that read the tokens, its tests, its stories in the catalog, the playground, the README and the change list) and runs the checks. |
| `/design-component` | Plan | toraline-ui - Runs the design process of one component before any code or Figma work (who uses it, the problem, how Intraweb and other libraries solve it, parts, variants, states, accessibility, tokens, props) and writes an approved design brief in the ticket. |
| `/design-screen` | Plan | toraline-ui - Runs the design process of one screen or flow of an app that uses the library (the person's goal, the steps, the content, the layout, the components it uses, the loading, empty and error states) and writes an approved design brief in the ticket. |
| `/figma-component` | Build | toraline-ui - Creates or updates one component in the library's Figma file from its approved design brief, with one Figma variant per variant, size and state, and every color, radius and font bound to a Figma variable. |
| `/review-component` | Deliver | toraline-ui - Compares one component in code, in Figma and in Intraweb with its approved design brief, in the light and the dark theme, and lists every difference with its severity and where to fix it; changes nothing. |
| `/sync-tokens-figma` | Deliver | toraline-ui - Compares the tokens in code with the variables in the library's Figma file, for each theme, and reports every difference in name, value or mode; changes one side only after a yes. |
