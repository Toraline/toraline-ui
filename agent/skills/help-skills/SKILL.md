# Help skills

Shows the skills of this repository in one list, grouped by stage (Start, Plan, Build, Deliver). It reads the catalog and the skill folders. It changes no file.

## Input

Nothing is required: `/help-skills`. Optional: one stage or one word to filter by, for example `/help-skills Plan` or `/help-skills review`.

## Reads

- Project profile in `AGENTS.md`: `packs`, `output_language`.
- `agent/rules/writing.md`.
- `docs/workflow/skills.md` (the catalog, generated by `make skills-catalog`).
- The header of every `agent/skills/*/SKILL.md`: `name`, `description`, `pack`, `stage`.
- `docs/workflow/working-pattern.md` (the order of the flow).

## Steps

1. List the skill folders: every `agent/skills/<name>/SKILL.md`. If there is none, report "no skills in `agent/skills/`" with the fix `make sync-skills`, and stop.
2. From each `SKILL.md`, read only the header between the two `---` lines: `name`, `description`, `metadata.pack`, `metadata.stage`. A skill with no `pack` counts as `project`. A skill with no `stage` goes in a group named "No stage".
3. Read `docs/workflow/skills.md`. Compare its skill names with the folder names from step 1.
   - Same names: use the headers from step 2 as the data.
   - The catalog is missing, or a name is in one place and not in the other: still use the headers from step 2. Record the difference for the report: which names are missing from the catalog, and which catalog names have no folder.
4. Read `packs` with `bash scripts/profile.sh get packs core`. A skill whose pack is not in `packs` is listed with the mark "pack is off".
5. If the person gave a stage or a word, keep only the skills whose stage, name or description contains it. If nothing matches, say so and show the full list.
6. Write one table per stage, in this order: Start, Plan, Build, Deliver, No stage. Inside a stage, order the skills as they appear in `docs/workflow/working-pattern.md`; skills not named there come after, in alphabetical order.

| Column | Content |
|---|---|
| Skill | `/<name>` |
| What it does | The first sentence of `description` |
| When to use it | One example phrase taken from `description` |
| Pack | `core`, `team` or `project`, plus "pack is off" when it applies |

7. Under the tables, add one line: "Every skill here runs only when you call it by name."
8. List only the skills of this repository. Do not list skills built into the tool, plugin skills or the person's own skills outside the repository, unless the person asks for them.

## Output

A fixed report, written in the profile's `output_language`:

- **Done:** the tables from step 6, with the number of skills per stage.
- **Not done:** the differences between `docs/workflow/skills.md` and `agent/skills/` from step 3, with the fix `make skills-catalog`; any `SKILL.md` whose header could not be read, by path.
- **Next step:** `start` (it asks your goal and names the skill to run).

## Do not

- Do not create, edit or delete any file. This skill does not run `make skills-catalog`; it names the command.
- Do not invent a skill, a description or a stage that is not in a header.
- Do not paste the body of a `SKILL.md`. Only the header fields are shown.
- Do not run any of the listed skills.
